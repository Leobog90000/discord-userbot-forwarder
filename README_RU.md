# Discord User-Bot — пересылка сообщений между каналами

[🇬🇧 English](README.md) | 🇷🇺 Русский

**Бот-юзер** (self-bot) на базе [`discord.py-self`](https://github.com/dolfies/discord.py-self), который автоматически пересылает сообщения из выбранных каналов Discord в другие каналы — в том числе на других серверах.

> ⚠️ **Предупреждение / только в ознакомительных целях.**
> Проект опубликован **исключительно для демонстрации того, как работает такой бот**. Автоматизация обычного пользовательского аккаунта («self-bot» / «бот-юзер») **нарушает [Условия использования Discord](https://discord.com/terms)** и может привести к **ограничению или бану аккаунта**. Вы используете этот код на свой страх и риск. Автор не несёт ответственности за последствия. Используйте отдельный запасной аккаунт, а не основной.

## Как это работает

Бот заходит в Discord как обычный **пользовательский аккаунт** (а не как официальное приложение-бот) по токену этого аккаунта.

- Он слушает **каналы-источники**, которые вы укажете.
- Каждое новое сообщение от **любого пользователя, кроме администраторов бота**, пересылается в связанный **целевой канал**.
- Пересылается только содержимое — **без имени автора, канала-источника и сервера**. Вложения перезаливаются; ссылки остаются обычными ссылками, а превью Discord строит сам.
- Сообщения администраторов воспринимаются **только как команды** и никогда не пересылаются.

**Важно:** аккаунт бота должен находиться **на всех задействованных серверах** — и на том, **откуда** пересылаются сообщения, и на том, **куда** они пересылаются. Например, чтобы пересылать из *Сервера 1 / Канала A* в *Сервер 2 / Канал B*, аккаунт должен состоять и на Сервере 1, и на Сервере 2, видеть Канал A и иметь право писать в Канал B.

## Возможности

- 🔁 Пересылка в реальном времени между любым количеством пар каналов (источник → цель)
- 🖼️ Перезаливка вложений (картинки/GIF — всегда; остальные файлы до 20 МБ, большие — ссылкой)
- 👮 Система администраторов — базовые владельцы в коде + админы, добавленные командой (сохраняются после перезапуска)
- 🧭 Управление парами каналов командами прямо во время работы (сохраняются после перезапуска)
- 🕰️ `!syncrange` — пересылка истории за выбранный период, с задержкой и лимитом сообщений для защиты

## Требования

- Python **3.9+**
- Аккаунт Discord (лучше **второй / запасной**), состоящий на всех нужных серверах
- Пакеты из `requirements.txt`: `discord.py-self`, `python-dotenv`

## Как получить токен

> По возможности используйте **второй аккаунт**. Подойдёт как самый новый, так и старый.
> **Никому не показывайте токен.** Тот, у кого он есть, получает полный доступ к аккаунту.

1. Откройте Discord **в браузере** (<https://discord.com/app>) и зайдите в аккаунт, который будет использоваться ботом.
2. Нажмите **F12** и выберите вкладку **Network** («Сеть»).
3. В поле **Filter** («Фильтр») введите `/api`.
4. Обновите страницу сочетанием **Ctrl+R** или клавишей **F5** и дождитесь появления списка запросов.
5. Среди имён найдите **`science`**. Таких элементов может быть несколько, поэтому иногда придётся проверить каждый, чтобы понять, в каком из них находится токен.
6. Внутри нужного `science` откройте вкладку **Headers** («Заголовки»).
7. Листайте список параметров, пока не найдёте **`authorization`**. После двоеточия отображается ваш индивидуальный **токен**.
8. Скопируйте его и вставьте в `.env`, заменив `your_user_token`:

```env
USER_TOKEN=your_user_token
```

## Настройка

### 1. Администраторы (`OWNER_IDS`)

Откройте файл бота (`botRU.py` или `botEN.py`) и замените ID-заглушки в `OWNER_IDS` на настоящие **ID пользователей**:

```python
OWNER_IDS = {
    111111111111111111,  # сам аккаунт бота
    222222222222222222,  # ваш основной аккаунт
}
```

Администраторы могут выполнять команды; их собственные сообщения **никогда** не пересылаются. Базовых владельцев нельзя удалить командой. Включите *Режим разработчика* в Discord (Настройки → Расширенные), затем ПКМ по пользователю → **Копировать ID пользователя**.

### 2. Пары каналов (`config.json`) — необязательно

Скопируйте `config.example.json` в `config.json` и впишите ID каналов (ПКМ по каналу → **Копировать ID канала**):

```json
{
  "source_servers": [
    {
      "channels": [
        { "source_id": "111111111111111111", "target_id": "222222222222222222" }
      ]
    }
  ]
}
```

Этот файл можно вообще не создавать и добавлять пары позже командой `!serverres add`.

## Запуск

Запустите **одну** из двух версий:

```bash
python botRU.py     # сообщения и справка на русском
python botEN.py     # сообщения и справка на английском
```

После старта в консоли появится `Вошли как ...`. Затем с аккаунта администратора отправьте `!helpres` в любой канал, который видит бот.

## Использование / команды

Префикс: `!` — команды работают только у администраторов.

| Команда | Описание |
|---|---|
| `!helpres` | Справка |
| `!aboutres` | Статус бота и активные пары |
| `!adminres list` | Список администраторов |
| `!adminres add <user_id>` | Добавить администратора |
| `!adminres remove <user_id>` | Убрать администратора (кроме базовых) |
| `!serverres list` | Список пар пересылки |
| `!serverres add <source_id> <target_id>` | Добавить пару |
| `!serverres remove <source_id>` | Убрать пару |
| `!syncrange <sources> <start> [end] [limit]` | Переслать историю за период |

**Подробнее про `!syncrange`**

- `<sources>` — один ID канала, несколько ID через запятую (без пробелов) или `all`
- Даты — `YYYY-MM-DD` или `YYYY-MM-DD HH:MM` (UTC). Если `end` не указан — берётся текущий момент
- `limit` — максимум сообщений **на каждый канал** (по умолчанию 500)

```text
!syncrange 111111111111111111 2025-01-01 2025-01-05
!syncrange 111111111111111111,222222222222222222 2025-01-01 2025-01-05
!syncrange all 2025-01-01 2025-01-05 200
```

**Пример полной настройки**

1. Добавьте аккаунт на Сервер 1 и Сервер 2.
2. Выполните `!serverres add <id-канала-A> <id-канала-B>`.
3. Теперь сообщение любого пользователя (кроме админов) из канала A будет появляться в канале B.

## Безопасность

- **Никогда не коммитьте `.env` и токен.** Приложенный `.gitignore` уже исключает `.env`, `config.json` и автоматически создаваемые JSON-файлы. Если токен утёк — сразу смените пароль аккаунта, это сделает токен недействительным.
- Не используйте основной аккаунт. Автоматизация пользовательских аккаунтов запрещена правилами Discord и может привести к бану.
- Не уменьшайте слишком сильно `SYNC_DELAY_SECONDS`, чтобы не упереться в лимиты.
